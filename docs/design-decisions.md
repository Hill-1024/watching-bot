# 设计决策记录

记录几个「为什么这么设计」,避免日后重构时把约束当成了随意。

## 1. 状态管理只监控 agent 本体,不认识任何模块

最初的想法容易滑向「状态管理盯着 QQ 消息算情绪」。但那样每接一个新能力模块就要改状态管理,解耦是假的。

定下的原则:**状态管理器的世界里只有 agent** —— 它消费的事件流是「LLM 转了一轮」「调用了一个带 social 标签的工具」「发生了一次归一化的 mention 感知」「时钟走了」。QQ 的内容(谁说的、说了什么)它永远看不到;社交电量因 `social` 标签的工具调用而消耗,烦躁因 mention 风暴而上升,这与"哪个 IM"无关。

推论:模块用**语义标签**(`toolTags`)向状态管理暴露行为的"性质",而不是让它读参数。换 IM 适配器、加沙箱电脑,状态管理一行不改。

## 2. 混合注入,而不是全部伪装成内心独白

体感/心情 → 伪造 assistant 消息(`<feeling>` 标签):拟人感最强,读起来就是"它自己想的"。
环境事件 → `[环境]` user 旁白:闹钟响、手机震是外部事实,如果也伪装成它的念头,会混淆因果(它的想法改变不了闹钟)。

两条底线:
- **状态数值永不进提示词**(疲惫=78 这类),只有主观描述,按区间查 `src/core/copy.ts` 文案表 —— 有单测断言文案不含数字;
- 所有注入写 `injections` 表,面板可回溯「它为什么这样」—— 调参靠猜是调不出来的。

## 3. 记忆分两层:pi 管日常压缩,我们只做睡眠归并

日常上下文膨胀是所有 agent 都有的问题,pi 的 compaction(摘要折叠)就是干这个的,不自研 —— 复用 `pi-coding-agent` 导出的纯函数(`shouldCompact`/`generateSummaryWithUsage`),挂在自己的 `transformContext` 钩子里。

我们设计的只有**睡眠期归并**:模型入睡时把当天经历写成日记(`memories/YYYY-MM-DD.md`)、把值得长期记住的事实(人物/关系/约定/偏好)合并进 `MEMORY.md` 索引(去重、归档过期),日记攒够一周再归并成周记。这模拟的是人类"睡一觉把短期记忆固化成长期记忆",与 pi 的机械压缩分工明确:热上下文靠 pi,睡醒仍该记得的靠归并。

## 4. 起床/入睡是工具,不是打断循环的询问

产品要求「循环是 infinite 的,模型自己选择」。落地:

- 自愿睡 = 调 `sleep` 工具;疲惫≥90 = 系统强制(`requestSleep`,不给模型选择);
- 被闹钟/@风暴打断 = 注入唤醒信号后**发起一次普通 run**,模型可以调 `wake_up`(真起)、也可以调 `sleep`(赖床)、甚至只回一句话(也算赖)—— loop 在 run 结束时检查:没确认起床就滚回 ASLEEP 并让响铃源重新排程;
- 自然醒/硬上限/面板强制 = 系统直接唤醒,不问模型(睡着了没有"决定权",这符合拟人直觉)。

防睡死的底线:闹钟重复响铃(每次真实重新入列,烦躁累积)+ 连续睡眠 12 模拟时硬上限 + 赖床 6 次强制拽醒。

## 5. 循环节奏:模型自驱 + 系统兜底

无限循环最大的工程风险是烧钱空转。节奏模型:

- 没事做 → 模型自己调 `wait`(它有放空的自由);
- run 结束后 loop 挂起,靠触发器驱动:wait 到期、闹钟、感知体感、状态命令、心跳兜底;
- 空响应(没调工具且没说什么)→ 心跳间隔指数退避,封顶 3 模拟时;
- 有待注入体感时 1 模拟分内 kick —— 感受要"及时",但也不为它单独付一轮调用,搭下一班车间。

## 6. 大模型网关直接复用 pi

`src/core/llm.ts` 不自己实现任何协议细节:目录路径用 pi 的 `builtinModels()`(40+ provider、型号元数据、标准 env key 解析全部现成);自定义 OpenAI 兼容端点用 pi 的 `createProvider` + 内置 openai-completions 实现注册。我们只写"选哪条路径"的 ~40 行胶水。faux 测试同样用 pi 自带的 faux provider。

## 7. NapCat 的引入方式:跨进程协议,不是库

NapCat 是挂在 QQ 上的独立客户端。watching-bot 通过 OneBot 11 WebSocket 与它通信(napcat 模块是协议客户端封装),因此:

- `third_party/napcat` submodule 只是源码/协议参考,不参与构建运行;
- 运行时用官方 Docker 镜像(compose 编排)或本机 shell 版;
- "未读"这类 OneBot 没有的概念,由模块自维护游标实现 —— napcat 模块是全项目唯一了解 QQ 的地方。
